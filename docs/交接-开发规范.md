## 一、三条铁律（违反会导致系统出问题）

### 铁律 1：加密只调用 `utils/crypto.py` 现成函数，不要自己写 gmssl

`utils/crypto.py` 已封装好并验证可用，直接 import：

```python
from app.utils.crypto import (
    hash_password,      # 注册时哈希密码：hash_password("明文") → "盐$哈希"
    verify_password,    # 登录时校验：verify_password("明文", "盐$哈希") → bool
    encrypt_field,      # 敏感字段加密：encrypt_field("13800138000") → hex串
    decrypt_field,      # 解密：decrypt_field(hex串) → "13800138000"
    mask_phone,         # 脱敏：mask_phone("13800138000") → "138****8000"
)
```

**绝对不要**自己 `from gmssl import ...` 重新写一套——gmssl 版本 API 易错，已经踩过坑了。

### 铁律 2：改借用记录状态 + 改设备状态，必须在同一事务

借用审批通过、确认归还时，要同时改两张表。参考 `api/borrow.py` 里 `approve_borrow` / `confirm_return` 的写法（`try/commit/except rollback` + `with_for_update()` 行锁）。**新写的任何涉及"改记录又改设备"的逻辑都照这个模式。**

### 铁律 3：配置全从 `config.py` 读，不硬编码

业务数值（最大借用天数、JWT过期时间、锁定次数等）都在 `config.py`，通过 `current_app.config["XXX"]` 读。新增可配置项就加到 `config.py` 和 `.env.example`，不要在业务代码里写死数字/密钥。

## 二、项目约定（照着抄就对）

### 统一响应格式
所有接口返回 `utils/response.py` 的 `success()` / `error()`：
```python
from app.utils.response import success, error
return success(data={...}, message="ok")        # 成功
return error("错误信息")                          # 业务错误，默认 code=1 http=400
return error("无权限", code=403, http_status=403) # 指定状态码
```

### 权限装饰器
每个业务接口加 `@require_permission('权限标识')`：
```python
from app.utils.auth_helper import require_permission, get_current_user_id
@xxx_bp.post("")
@require_permission("device:create")
def create_xxx():
    uid = get_current_user_id()   # 当前登录用户ID
    ...
```
权限标识清单见 `docs/数据库设计说明.md` 的权限矩阵。

### 输入安全
用户提交的文本字段一律先过 `sanitize_input()`（防XSS）：
```python
from app.utils.validators import sanitize_input, check_required
name = sanitize_input((data.get("name") or "").strip())
```

### 审计日志
关键操作后调 `log_action()`：
```python
from app.utils.audit import log_action
log_action("USER_UPDATE", f"用户ID:{uid}", "改了什么")
```

### 蓝图注册
新写的蓝图要在 `app/__init__.py` 的「注册蓝图」段加一行
`app.register_blueprint(xxx_bp, url_prefix="/api/xxx")`。

## 三、如何运行验证

```bash
# 1. 起数据库（项目根目录）
docker-compose -f docker-compose.dev.yml up -d

# 2. 后端（backend 目录）
source venv/Scripts/activate
export FLASK_APP=app
flask init-db          # 首次：建表+种子数据+超管账号
flask run --port=5000

# 3. 前端（frontend 目录）
npx vite --port=5173
```

超管账号：`superadmin` / `Admin@123456`（见 `.env`）

验证某个新接口是否注册成功：
```bash
python -c "from app import create_app; app=create_app(); [print(r) for r in app.url_map.iter_rules()]"
```

### 关键设计决策（答辩可讲）
1. **前后端同域部署**：Nginx 同时托管前端静态文件和 `/api` 反代，前端无需关心后端地址，且天然规避跨域问题。
2. **Gunicorn 只监听 127.0.0.1:5000**：后端绝不直接对公网暴露，所有流量必须经 Nginx，符合最小暴露面原则。
3. **ProxyFix 信任 1 层代理**：审计日志能记到客户端真实 IP（不是 127.0.0.1），且只信任 1 层防止 XFF 头伪造。
4. **配置与代码分离**：生产/开发用同一套代码，靠 `FLASK_ENV` 环境变量切换，零硬编码。

## 三、云服务器部署步骤（按顺序执行）

> 假设：代码部署在 `/opt/lab/project`，部署用户 `labuser`。如果路径/用户名不同，记得同步改
> `deploy/lab-backend.service` 里的三处路径。

### 步骤 0：上传代码
```bash
# 本地把 project 整个传上去（git clone 或 scp 均可）。注意 venv/node_modules 不用传
# 推荐 git：服务器上
sudo mkdir -p /opt/lab && sudo chown labuser:labuser /opt/lab
cd /opt/lab
git clone <你的仓库地址> project   # 或用 scp 上传
```

### 步骤 1：装系统环境
```bash
sudo apt update
sudo apt install -y python3 python3-venv python3-pip mysql-server redis-server nginx git curl
```

### 步骤 2：配置 MySQL
```bash
sudo mysql <<'SQL'
CREATE DATABASE IF NOT EXISTS lab_device_db
  CHARACTER SET utf8mb4 COLLATE utf8mb4_general_ci;
CREATE USER IF NOT EXISTS 'lab_user'@'localhost' IDENTIFIED BY '【你的数据库强密码】';
GRANT ALL PRIVILEGES ON lab_device_db.* TO 'lab_user'@'localhost';
FLUSH PRIVILEGES;
SQL
```
> MySQL 默认只监听 127.0.0.1，无需额外配置即满足"数据库不对公网开放"。

### 步骤 3：后端环境
```bash
cd /opt/lab/project/backend
python3 -m venv venv
source venv/bin/activate
pip install -r requirements.txt

# 生成生产 .env
# ⚠️ 重要改动：.env.production.example 已经填好所有真实密码和密钥
# 直接用，无需再手动替换（但上云后建议在服务器上重新生成一轮）
cp .env.production.example .env
# 不需要 nano 编辑，密码密钥都已填好。但建议打开看一眼确认格式正确
nano .env

# 初始化数据库表 + 种子数据（3角色/18权限/超管账号）
export FLASK_ENV=production
flask init-db
```

### 步骤 4：前端构建
```bash
cd /opt/lab/project/frontend
# 装 node（若没有）：用 nvm 或 apt 装 node 18+
npm install
npm run build          # 自动读 .env.production，产出 dist/

# 把 dist 放到 Nginx 根目录
sudo mkdir -p /var/www/lab
sudo cp -r dist /var/www/lab/
```

### 步骤 5：启动后端服务（systemd）
```bash
cd /opt/lab/project
sudo cp deploy/lab-backend.service /etc/systemd/system/
# ⚠️ 先确认 service 里的 User / WorkingDirectory / ExecStart 路径与实际一致
sudo systemctl daemon-reload
sudo systemctl enable --now lab-backend
sudo systemctl status lab-backend     # 应显示 active (running)
curl http://127.0.0.1:5000/api/health  # 应返回 {"code":0,...}
```

### 步骤 6：生成 HTTPS 证书 + 配置 Nginx
```bash
cd /opt/lab/project
sudo bash deploy/gen_cert.sh           # 无域名自动用公网IP；有域名：sudo bash deploy/gen_cert.sh 你的域名

sudo cp deploy/nginx/lab.conf /etc/nginx/sites-available/lab.conf
sudo ln -sf /etc/nginx/sites-available/lab.conf /etc/nginx/sites-enabled/
sudo rm -f /etc/nginx/sites-enabled/default
sudo nginx -t                          # 语法检查必须 OK
sudo systemctl reload nginx
```

### 步骤 7：防火墙
```bash
sudo ufw allow 22/tcp      # SSH
sudo ufw allow 80/tcp      # HTTP（会自动跳 443）
sudo ufw allow 443/tcp     # HTTPS
sudo ufw enable
sudo ufw status            # 确认 MySQL(3306)/Redis(6379) 没开放给公网
```

### 步骤 8：数据库定时备份
```bash
chmod +x /opt/lab/project/deploy/backup.sh
crontab -e
# 加一行：每天凌晨 3:07 自动备份
7 3 * * * /opt/lab/project/deploy/backup.sh >> /var/log/lab-backup.log 2>&1
```

## 五、常见坑（DeepSeek 排错参考）

| 现象 | 原因 | 解决 |
|------|------|------|
| 502 Bad Gateway | 后端没起 / 端口不对 | `systemctl status lab-backend`，看 `journalctl -u lab-backend -f` |
| 前端能开但接口全 404/跨域 | dist 是旧的 / baseURL 不对 | 确认 `npm run build` 用了 .env.production，重新 build+cp |
| 日志 IP 全是 127.0.0.1 | FLASK_ENV 不是 production，ProxyFix 没生效 | 检查 service 里 `Environment=FLASK_ENV=production` |
| `flask init-db` 连不上库 | .env 数据库密码错 / MySQL 没起 | 核对 .env 的 DB_PASSWORD，`systemctl status mysql` |
| gmssl 报错起不来 | 国密库环境问题 | 临时把 .env 的 `CRYPTO_BACKEND=openssl` 先跑通，再排查 |
| Nginx reload 失败 | 证书路径不存在 | 先跑 gen_cert.sh，确认 /etc/nginx/ssl/lab.crt 存在 |

> 注意：切换 CRYPTO_BACKEND 会导致已有密码哈希/加密字段无法解开。一旦上线产生真实数据就别再换后端。
